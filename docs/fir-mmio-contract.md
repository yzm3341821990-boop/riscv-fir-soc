# FIR MMIO 与共享 RAM v1

标识 `fir-mmio-1k-v1`。使用既有 `fir-serial-stream-v1` 运算核及 `fir-q15-block-v1` 数值规则；单时钟、上升沿、高有效同步复位。本步为功能系统，不改变默认 CPU 的 RAM 范围；只有 `ENABLE_FIR_MMIO=true` 的实例开放寄存器页。

## 地址与寄存器

CPU 指令 ROM 和数据 RAM 仍各 1 KiB，地址 0～1023，彼此独立。FIR 基址为 `0x40003000`，页大小 4 KiB。只接受对齐的 LW/SW；CPU 对该页的字节/半字指令进入 FAULT。RAM 的字节/半字规则不变。寄存器读取在请求边沿登记，下一拍供 CPU 写回，不插入 CPU 等待周期。

| 偏移 | 名称 | 规则 |
| --- | --- | --- |
| 0x00 | CONTROL | 写 1=START，2=ACK，0=无操作；读取 0 |
| 0x04 | STATUS | bit0 BUSY，bit1 DONE，bit2 ERROR；其余 0 |
| 0x08 | SRC_ADDR | 空闲时可读写，输入 RAM 字节地址 |
| 0x0C | DST_ADDR | 空闲时可读写，输出 RAM 字节地址 |
| 0x10 | SAMPLE_COUNT | 空闲时可读写；合法任务为 1～128 个样本 |
| 0x14 | CYCLES | 只读；START 接受到最后一次写入接受之间的时钟间隔，32 位回绕 |
| 0x18 | WRITTEN | 只读；本次任务已成功写入的输出数量 |
| 0x1C | ERROR_CODE | 只读；首个错误码，直到 ACK/有效 START/复位 |
| 0x100～0x17C | H[0]～H[31] | 空闲时可读写，32 位符号扩展的 signed16 系数 |

未定义地址读取 0 并记录错误 8。写只读寄存器、非完整字节使能或未定义地址也记录错误 8。所有 32 个系数必须在复位后合法写过，才可启动；ACK、结束和新任务均保留系数。每个 START 都在内部先清历史，不输出卷积尾部。

START 接受前依次检查样本数、对齐、范围、缓冲重叠、系数就绪。每个样本占 4 字节，低 16 位为 Q15 原始整数，高 16 位必须为符号扩展。整个输入/输出区必须在 0～1023 内，且互不重叠；128 是两个不重叠缓冲区能同时放入本 RAM 的最大长度。

有效 START 清 DONE/ERROR/计数并置 BUSY。空闲 ACK 清 DONE、ERROR、错误码，不修改配置、系数或 RAM。BUSY 时所有寄存器写入（含重复 START、ACK、配置和系数）均拒绝，记录错误 1，原任务继续；读仍允许。ERROR 为粘滞位，可与 BUSY/DONE 共存，后续错误不覆盖首个错误码。

| 错误码 | 原因 |
| --- | --- |
| 1 | BUSY 时写入 |
| 2 | 样本数为 0 或大于 128 |
| 3 | 源/目的地址非 4 字节对齐 |
| 4 | RAM 地址或整个缓冲区越界 |
| 5 | 输入/输出缓冲区重叠 |
| 6 | 系数未全部配置 |
| 7 | 系数或读取的输入不满足 signed16 符号扩展 |
| 8 | 无效寄存器、写只读位置或非法字节使能 |
| 9 | 未定义 CONTROL 命令 |

配置拒绝不产生 DMA 事务。运行中遇到错误输入编码时中止，BUSY=0、DONE=0、ERROR=1，先前已写的部分输出保留，但整个输出缓冲区无效。无总线异常/中断接口；软件检查 STATUS/ERROR_CODE。固件须设置有限轮询上限。

当前八样本 C 示例最多轮询 64 次。若超时或状态异常，设置 C 的 errors=1、done=1 并返回 1，不再访问任务缓冲区。软件超时不自动撤销硬件请求：下游永久暂停时硬件仍 BUSY，须全局复位后才能重新使用其缓冲区。C 的 done 只表示程序结束检查，不代替硬件 DONE；正常成功必须同时观察 C errors=0、FIR STATUS=2、WRITTEN=N。

## 同步 RAM 与完成语义

RAM A 端口供 CPU（或复位装载阶段的 testbench），B 端口供 FIR。两端口均为同步读；A 支持字节使能，B 只传输整字。B 请求在 `dma_req && dma_ready && !rst` 的边沿接受，等待时地址、方向、写数据不变。读返回在接受边沿之后产生一次 rvalid；写在接受边沿更新 RAM，不另返回读响应。暂停可以无限长，验证环境提供有限暂停及超时。

FIR 依次执行清历史、请求读、等待读响应、输入握手、等待计算结果、请求写。最后输出写入被接受的同一边沿才置 DONE、清 BUSY；等待最后写入期间必须保持 BUSY=1、DONE=0。WRITTEN 仅在写入被接受时加一。每个独立任务恰好 N 次 RAM 读和 N 次 RAM 写。

CPU 软件在 BUSY 期间不得访问任务输入/输出缓冲区或修改系数/配置；可以轮询寄存器、使用不相交的栈和其他 RAM。协议测试检查这一约束以及双端口写冲突。当前无缓存，不需要缓存维护；不应把该性质推广到未来有缓存的 CPU。

全局复位屏蔽新 DMA 接受并取消任务，清状态、配置和全部系数，RAM 保留。已完成的写入不回滚；软件把整个旧输出视为无效，重新配置后重试。testbench 装载 RAM 不是已实现的板上启动流程。

当前只比较相同数据的计算正确性。系统计数包含 DMA 等待，但不自动包含 CPU 配置/轮询/结果核对时间；不同固件和布局的仿真结束时刻不能直接构成公平加速比。资源、主频、综合和上板另行验证。

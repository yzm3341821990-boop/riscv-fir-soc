# FIR 数值契约 v1

契约标识：`fir-q15-block-v1`。这是 Python、未来 CPU 上的 C 程序和 FIR RTL 共同遵循的算术规范。

## 表示方式与运算

| 量 | 表示 | 数值含义 |
| --- | --- | --- |
| 输入 X、系数 H | 16 位二进制补码整数 | 实数值 = 整数 / 32768 |
| 单个乘积 | 有符号 32 位，30 个小数位 | 乘积实数值 = 整数 / 2^30 |
| 累加器 A | 有符号 40 位，30 个小数位 | 32 个原始乘积相加，中间不舍入 |
| 输出 Y | 16 位二进制补码整数 | 实数值 = 整数 / 32768 |

输入与系数整数范围都是 `[-32768,32767]`，对应实数范围 `[-1,1-2^-15]`。正数 +1 无法准确编码；因此脉冲测试使用幅度 0.5（整数 16384），而不是非法整数 32768。

抽头数固定为 32，`H[0]` 乘当前样本：

`A[n] = Σ H[k] * X[n-k]`，`k=0..31`。

每次调用清零历史：`X[j]=0`（`j<0`）。N 个输入产生 N 个输出，不附加长度 31 的卷积尾部。空输入产生空输出，但仍须提供合法的 32 个系数。

舍入后的整数定义为：

`R(A) = sign(A) * floor((abs(A) + 16384) / 32768)`。

这表示舍入至最近整数，恰好半格时远离零；不能直接套用 Python 的 `round()`（半格取偶数），也不能直接算术右移负数。

最终 `Y = min(32767, max(-32768, R(A)))`。超限时饱和，不按 16 位回绕。

| 累加器整数 A | 舍入后的整数 | 说明 |
| --- | --- | --- |
| 16383 | 0 | 正半格以下 |
| 16384 | 1 | 正半格 |
| -16383 | 0 | 负半格以内 |
| -16384 | -1 | 负半格 |
| 49152 | 2 | 正 1.5 格 |
| -49152 | -2 | 负 1.5 格 |

最坏正累加为 `32 * (-32768) * (-32768) = 2^35 = 34359738368`。有符号 36 位的最大值是 `2^35-1`，因此至少需要 37 位；本项目使用 40 位。Python 使用任意精度整数计算，转换输出时检查 40 位范围，不用溢出回绕掩盖位宽错误。

输入原始整数不接受浮点数或布尔值；需要从实数转换时显式调用 `quantize_q15()`。此函数使用同一舍入和饱和方向，并拒绝 NaN/无穷大。

## 块边界

`fir_block()` 是无状态的独立块参考。将一个连续信号拆成多个块分别调用，会在每个块首重新产生零历史瞬态。连续流模式需要另行规定历史保留、启动和复位策略，不能把当前独立块结果直接当成连续音频处理结果。

数值模型没有时钟、总线和指令执行时间；不能用于推断 FPGA 主频或加速比。空块的数学行为也不等于硬件 MMIO 对零样本任务的处理规则。

## 测试向量格式

`vectors/manifest.json` 记录契约、用例、固定种子、生成源码 SHA-256，以及各文件的 SHA-256。所有文本使用 ASCII、LF 换行，无时间戳或本机路径。

每个用例包含：

- `input.hex`：每行一个输入，16 位有符号值扩展为 32 位字，8 个十六进制字符。
- `coefficients.hex`：恰好 32 行，顺序为 H[0] 到 H[31]，同样符号扩展为 32 位。
- `expected.hex`：每行一个期望输出，32 位符号扩展格式。
- `accumulators.hex`：每行一个原始累加器，40 位二进制补码，10 个十六进制字符。
- `trace.csv`：`n,input,accumulator,output`，均为十进制整数，便于人工检查。

例如：0 → `00000000`；32767 → `00007FFF`；-1 → `FFFFFFFF`；-32768 → `FFFF8000`。`0000FFFF` 不是合法的 -1 符号扩展，应拒绝。

十六进制文件按“字”列值；装入字节寻址内存时采用小端序，例如 `00007FFF` 对应字节 `FF 7F 00 00`。每个样本占 4 字节，样本地址依次增加 4；文件自身不包含地址或总线周期。

生成命令：`python -m tools.generate_vectors`。

独立检查命令：`python -m tools.verify_vectors vectors`。检查器不调用生产模型及其舍入函数，而采用输入贡献向后散布的卷积与 `fractions.Fraction` 舍入核对结果，同时核对文件哈希、符号扩展、长度和 CSV。

此契约若改变舍入、饱和、抽头顺序或历史规则，须升级契约标识、更新测试，并重新生成和审查全部向量。

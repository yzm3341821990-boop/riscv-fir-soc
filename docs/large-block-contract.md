# 长块 FIR 与 32 KiB 片上存储契约

标识 `fir-large-block-v1`。本轮另建候选，不修改已经编译的 step19 三个工程。32 抽头定点语义与 1/2/4 路运算核沿用既有契约；新范围是更大 RAM、访问边界和 64/256/1024 样本完整调用。

共享 RAM 为 8192×32 位，即 32 KiB，字节地址 0～32767。CPU A 端口支持 4 个字节写使能；DMA B 端口读写完整 32 位字，地址必须对齐。所有端口同属核心时钟域。两端读取的同步延迟为一个接受边沿，B 在接受读请求的边沿后给出 rvalid 和对应数据；复位取消 B 的握手和响应，保留存储内容。A 端口在 CPU 复位期间仍可供启动装载器写入，复位不清整个 RAM。

存储使用 Quartus 17 已安装 `altera_mf.altsyncram` 原语，明确要求 Cyclone IV E / M9K / BIDIR_DUAL_PORT、32 位双端口及字节使能。不以通用寄存器数组假定实现为块 RAM；实际 M9K 数量、资源及时序由用户编译确认。ModelSim 使用同版本预编译 altera_mf 库，原语参数以本机 `quartus/eda/sim_lib/altera_mf_components.vhd` 为准。

不同字可同时访问，同一字的双读也可并行。同一字且任一端口写时，A 优先，B 的 ready 拉低；B 发送者须保持请求和地址/数据，直到之后真正接受。这样不会依赖 M9K 未定义的混合端口读写冲突结果：A 写/B 读被排序为先写后读，A 读/B 写被排序为先读后写，双写被排序为 A 后 B。

新 CPU 数据访问限制扩展到低地址 32 KiB，仍保持字节/半字/字对齐规则、同步读延迟和既有流水线暂停/旁路。程序 ROM 独立，容量仍为 1 KiB。FIR MMIO 页仍为 0x40003000，系数、状态与错误规则不变；合法任务最多 4096 样本且输入/输出完整位于 RAM、互不重叠，START 前验证。

长块固件固定同一编译器/指令子集，软件、冷调用、系数驻留调用采用相同数据布局与初始 RAM；每种 N 的源样本、32 个系数、输出和参考期望值均完整保存在片上 RAM。C 在计时区间后核对全部 N 个结果。完整调用仍是两次接受的 marker 写入沿之差；系数驻留装载不在主区间内但须记录。内核 CYCLES、完整调用和板级自检分别报告。

主要长度为 64、256、1024。全部输入与期望输出由固定种子、独立参考检查确定，不以只检查首八个输出替代完整长块验证。保留实际接受的总线、DMA、提交及结束状态证据；对地址别名、字节使能、冲突排序、越界保护和结果破坏做受控错误验证。

本轮只由 Agent 运行功能仿真并准备工程；Quartus 全编译、SOF 下载及板卡操作仍由用户执行。新 M9K 路径的实现结论不能沿用 step19 的寄存器型 RAM 报告。

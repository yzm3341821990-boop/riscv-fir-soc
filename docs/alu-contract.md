# ALU32 接口与算术约定

契约：`alu32-rv32i-v1`。HDL 采用 VHDL-93，面向当前 ModelSim 10.5b/Quartus 17 环境。

模块 `alu32` 为组合逻辑，输入 `a[31:0]`、`b[31:0]`、`alu_op[3:0]`，输出 `result[31:0]`。接口没有时钟或状态；后续流水线寄存器负责采样结果。功能仿真的等待时间不是 FPGA 电路延迟指标。

| alu_op | 操作 | 结果 |
| --- | --- | --- |
| 0 | ADD | a+b 的低 32 位 |
| 1 | SUB | a-b 的低 32 位 |
| 2 | AND | 按位与 |
| 3 | OR | 按位或 |
| 4 | XOR | 按位异或 |
| 5 | SLL | a 左移 b 的低 5 位所表示的位数 |
| 6 | SRL | a 逻辑右移，高位补零 |
| 7 | SRA | a 按有符号数算术右移，高位复制符号位 |
| 8 | SLT | signed(a)<signed(b) 时为 00000001，否则为 00000000 |
| 9 | SLTU | unsigned(a)<unsigned(b) 时为 00000001，否则为 00000000 |
| A..F | 保留 | 输出 00000000 |

操作码是 CPU 内部控制编码，不是完整 RISC-V 指令的 opcode 字段。加减使用模 2^32 算术，不采用 FIR 的 Q15 饱和规则。二进制移位量 32 的低五位为 0，所以移位量实际为 0。

契约针对 0/1 二进制输入；包含 U/X/Z 的数据不作为合法运算输入。当前模块没有状态标志寄存器、乘除单元、分支译码或异常处理。保留 ALU 操作码的默认值不代替 CPU 对非法指令的处理。

验证以定向向量、边界值交叉组合和固定种子随机向量检查；每条向量比较完整的 32 位结果。检查器必须拒绝输入文件错误、空文件、数量不符和任何结果不一致。还要把 SRA 故意改成逻辑右移，确认相同 testbench 失败并使批处理返回非零退出码。

本阶段仅验证 ALU 的 RTL 功能，综合、布局布线、时序及上板证据分别在后续取得。

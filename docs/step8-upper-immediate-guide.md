# 第八步：构造 32 位常量，计算相对地址

最新 [第十步](step10-c-program-guide.md) 已运行编译的裸机 C 示例；本页保留对应历史阶段的学习内容及限制。

本页保留第八步示例及其历史验证结果。当前版本已进入 [第九步：字节与半字读写](step9-subword-guide.md)，原示例继续可用；本页的 31 指令计数属于当时版本。当前回归结果写入 [第九步报告](../reports/step10-c-program/validation.json)。

前一步让 CPU 能执行循环。这一步补上 LUI 与 AUIPC，使 CPU 能方便地构造完整的 32 位常量、计算相对当前指令的地址，再与已有的跳转和 RAM 读写连接。后续的编译程序需要这些能力来定位数据和代码。

当前支持 31 种指令。本次示范先得到 `0x12345678`，写入 RAM 字节地址 64 并读回；接着用 AUIPC/ADDI 算出目标地址，通过 JALR 跳过一条清零内存的指令，最后确认 RAM 中仍是原来的常量。这里的 31 指令范围见 [CPU 契约](tiny-cpu-contract.md)，尚未覆盖完整 RV32I。

## 在 ModelSim 中运行

在底部 Transcript 提示符后输入这一条命令：

```tcl
do {F:/CodexWorkspace/outputs/riscv-fir-soc/tiny_cpu/baseline/run_upper_gui.do}
```

脚本会先卸载旧设计，再切换目录、编译、运行并加入波形。默认游标停在 **276 ns**，此时最后一次读回已写入寄存器，testbench 也完成了检查。

## 先看最后的结果

这次寄存器、RAM、PC 和提交值统一按十六进制显示，`retired_count` 按十进制显示。

| 波形 | 最终值 | 含义 |
| --- | --- | --- |
| x1 | `12345678` | LUI/ADDI 构造出的 32 位常量 |
| x2 | `12345678` | 第一次从 RAM 读回的值 |
| x3 | `00000020` | 计算出的跳转目标；十进制地址 32 |
| x4 | `0000001C` | JALR 保存的返回地址；十进制地址 28 |
| RAM_byte64 | `12345678` | 字节地址 64 的实际内存内容 |
| x5 | `12345678` | 跳过清零指令后，再次读回的值 |
| retired_count | 8 | 实际完成的指令次数 |
| finished | TRUE | testbench 检查完成并停止时钟 |

`12345678` 在这里是十六进制，完整写法为 `0x12345678`，十进制等于 305419896。内存字节地址 64 的十六进制是 `00000040`；内部数组按 32 位字编号，因此对应 `bank(16)`。

## LUI 怎样构造大常量

普通 ADDI 只有 12 位有符号立即数，范围为 −2048～2047。LUI 把指令里的 20 位数据放到结果的高 20 位，低 12 位补零。因此本例先用 `lui x1, 0x12345` 得到 `0x12345000`，再用 `addi x1, x1, 0x678` 加上 1656，得到 `0x12345678`。[RISC-V RV32I 规范](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html)定义了这两条指令的立即数形式。

LUI 的汇编参数 `0x12345` 是尚未左移的 20 位字段。把 `0x12345000` 直接作为该字段输入会超出范围。这里低 12 位 `0x678` 小于 `0x800`，能直接作为正 ADDI 立即数；若低段的最高位为 1，ADDI 会把它解释成负数，需要调整前面的高段。自动测试也检查这种组合。

LUI 不读取源寄存器；指令中通常用于 rs1/funct3 的那些位置，在 U 型编码里都属于立即数。即使相同编号的普通寄存器此前有非零值，也不能影响 LUI 的结果。

## AUIPC 怎样得到跳转目标

AUIPC 也把 20 位字段左移 12 位，但会再加上**该条 AUIPC 自身的地址**。本例在地址 `0x10` 执行 `auipc x3, 0`，因此先得到 `x3=0x10`；下一条 ADDI 加上十进制 16，得到 `x3=0x20`。

地址 `0x18` 的 JALR 使用这个 x3 作为目标，跳到 `0x20`，同时将自身地址加 4，即 `0x1C`，保存到 x4。地址 `0x1C` 的 `sw x0,64(x0)` 被跳过，没有执行，因此不会把 RAM 清零。最后的 LW 仍读回 `0x12345678`。这里“保存了返回地址”不表示程序已执行返回；本示范只检查返回地址写入与目标选择。

源程序见 [upper_demo.S](../programs/upper_demo.S)，对应机器码见 [upper_demo.hex](../programs/upper_demo.hex)。

| PC（十六进制） | 指令 | 作用 |
| --- | --- | --- |
| 00 | `lui x1, 0x12345` | x1=`12345000` |
| 04 | `addi x1, x1, 0x678` | x1=`12345678` |
| 08 | `sw x1, 64(x0)` | 把常量存入 RAM |
| 0C | `lw x2, 64(x0)` | 第一次读回常量 |
| 10 | `auipc x3, 0` | 取这条指令的地址，x3=`00000010` |
| 14 | `addi x3, x3, 16` | x3=`00000020` |
| 18 | `jalr x4, x3, 0` | 跳到 20，x4=`0000001C` |
| 1C | `sw x0, 64(x0)` | 被跳过；若误执行会清零 RAM |
| 20 | `lw x5, 64(x0)` | 再次确认常量仍在 |

文件中有九条静态指令，运行时跳过其中一条，因此完成八次提交。RAM 请求只能有三笔：一次写入、两次读取；不能出现向地址 64 写零的请求。

## 波形的关键时刻

先观察 `commit_valid`、`commit_pc` 与 `commit_value`。提交时，`commit_pc` 表示刚完成的指令地址；当前 PC 已在同一上升沿更新为下一条地址。

| CPU 上升沿时刻 | 观察点 |
| --- | --- |
| 45 ns | LUI 完成，x1=`12345000` |
| 75 ns | ADDI 完成，x1=`12345678` |
| 105 ns | SW 被 RAM 接受，RAM_byte64=`12345678` |
| 135 ns | 第一次 LW 读请求被接受 |
| 145 ns | 第一次 LW 写回，x2=`12345678` |
| 175 ns | AUIPC 完成，x3=`00000010` |
| 205 ns | ADDI 完成，x3=`00000020` |
| 235 ns | JALR 完成，x4=`0000001C`，PC 跳到 `00000020` |
| 265 ns | 最后的 LW 读请求被接受 |
| 275 ns | 最后的 LW 写回，x5=`12345678` |
| 276 ns | testbench 核对完成，retired_count=8、finished=TRUE |

testbench 在每个上升沿后等待 1 ns 才核对并打印提交，因此日志会显示 46、76、146、176、236、276 ns 等检查时间。表中的 CPU 动作时刻与日志检查时刻相差 1 ns，这是检查等待造成的。

如果只想看大常量的形成，放大到 35～85 ns；如果想看 AUIPC 与跳转，放大到 165～245 ns。`commit_pc` 应从 `18` 直接到 `20`，没有 `1C` 的提交。再检查 `dmem_req/dmem_we`，确认没有被跳过的清零写请求。

波形中的 `immediate` 给出形成后的 32 位立即数。LUI 执行时，这里显示补过低 12 位零的 `12345000`；本例 AUIPC 的该值为零，写回结果还需要加上当前指令地址。判断已经完成的结果时，先看 `commit_value` 或实际目标寄存器，不要把立即数本身当作 AUIPC 的最终写回值。

## 当前边界

AUIPC 的架构运算保留低 32 位；但在当前 1 KiB ROM 中，可达 PC 小于 1024，U 的低 12 位又全部为零，无法在整核程序中制造 AUIPC 加法自身的 32 位进位回绕。高位 U 值、负偏移表示与后续 ADDI 回绕的测试不应被称为已经观察到 AUIPC 自身溢出。

大常量可以保存在寄存器中，但当前 RAM 仍只允许 0～1020 的四字节对齐起始地址。构造出很大的数不代表可以访问那么大的内存；实际分支/跳转目标也受固定 ROM 范围限制。详细规则见 [CPU 契约](tiny-cpu-contract.md)。

当前尚无完整 RV32I、标准异常处理、C 运行环境或流水线。演示结束由 testbench 停止时钟，没有新增 HALT 指令。证据范围是 Python 和 RTL 功能仿真；Quartus 综合、M9K 推断、资源、时序与 DE2-115 实机行为仍需后续验证。

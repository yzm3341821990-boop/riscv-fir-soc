# DE2-115 参考编译工程 v1

标识 `de2-reference-boot-v1`。本步为原 CPU/FIR SoC 增加可综合的 ROM、复位、启动装载与 LED 自检顶层。目标是得到可打开、可重复编译的 Quartus 工程；没有自动编程开发板。

## 参考目标与物理边界

参考器件选择 `EP4CE115F29C7`、Cyclone IV E。用户照片已确认板名 DE2-115，但实际芯片完整封装/速度等级与电压跳线尚未现场核实；当前结果只针对该参考器件。下载前需对照实际板卡，不能把参考编译当成实物确认。

引脚与电压依据 Terasic 官方用户手册的时钟表 4-5、按键表 4-2、LED 表 4-3 和 JP7 表 4-8：

| 顶层端口 | 板卡信号 | 引脚 | 参考 I/O 标准 |
| --- | --- | --- | --- |
| CLOCK_50 | CLOCK_50 | Y2 | 3.3-V LVTTL，50 MHz / 20 ns |
| RESET_N | KEY[0] | M23 | 2.5 V，前提为 JP7 默认 2.5 V |
| LEDR[0] | LEDR[0] | G19 | 2.5 V，程序完成 |
| LEDR[1] | LEDR[1] | F19 | 2.5 V，结果通过 |
| LEDR[2] | LEDR[2] | E19 | 2.5 V，错误/超时 |

来源：[Terasic DE2-115 用户手册](https://www.terasic.com.tw/wiki/images/f/ff/DE2_115_User_manual_2013.pdf)、[官方镜像](https://www.terasic.com.tw/attachment/archive/502/DE2_115_User_manual.pdf)。按键所在电压取决于 JP7，不能在未核对实物时假定所有输入都是 3.3 V。未使用引脚设为输入三态。

## 启动与复位

板载 CLOCK_50 驱动一个自由运行的二分频寄存器，生成 25 MHz 系统时钟。该分频器不受按键复位控制，避免复位按钮截短其脉冲。外部低有效 KEY0 异步置位两级复位寄存器，高电平释放经过两个系统时钟边沿。上电初值也保持这两级为复位状态。内部控制、CPU、ROM、RAM 与 FIR 均使用同一个 25 MHz 时钟；心跳只用于 LED，不再生成其他时钟。

程序与初始 RAM 镜像来自已校验的 `programs/c_fir_accel` ELF。镜像生成到纯 VHDL 常量 ROM，不在可综合 RTL 内使用文件 I/O。程序 ROM 为同步一拍读，未用的指令字填 NOP；种子 ROM 保存完整 256 个 RAM 字。

每次上电/KEY0 复位后，装载器经真实 RAM A 端口依次覆盖全部 256 个字，包括全局变量、输出与栈初值。种子 ROM 读与写之间隔一拍，不能把旧 ROM 数据写到下个地址。装载完成之前 CPU 与 FIR 保持复位；完成后才释放 CPU，运行原 C 驱动。由此重复按键不会沿用上次的 polls/done/errors。

## 自检与停止

监测实际被 RAM 接受的八次 DMA 输出写入，检查字地址、顺序和完整 32 位符号扩展结果。另监测 C 的 done/errors 写入及 CPU FAULT。在程序末尾 PC 哨兵处，必须同时满足 C done=1、errors=0、八个 DMA 输出均正确，才能锁存 PASS。

到达末尾后用已有 host_active 接口保持 CPU 复位，避免执行 ROM 填充区；正常完成的 FIR 状态保持。发生 FAULT、错误结果或超时则取消系统任务。RAM 不靠复位清零，下次按键由装载器明确重载。

LEDR0 为锁存完成，LEDR1 为锁存通过，LEDR2 为锁存错误，LEDR3 为系统时钟计数器的一位，仅驱动 LED，不用于内部时钟。超时阈值为 2^20 个系统时钟；人眼心跳使用 bit24，仿真可以缩短此 LED 参数。

## 约束与证据

SDC 定义 20 ns 主时钟，并对真实分频寄存器声明 divide_by=2 的 40 ns 生成时钟，再派生时钟不确定度。不是仅放宽 SDC 而继续让 CPU 运行在 50 MHz。KEY0 只到复位同步链的异步路径被排除；同步链到系统的时钟路径仍分析。LED 是异步的人眼观察输出，不是外部时钟采样总线，因此 LED 输出端点显式排除时序分析；不能把该例外用于未来 UART/存储器等接口。

保留 ModelSim 的自动启动、重复按键、装载中复位、运算中复位检查，并用错误结果/错误 ROM 装载受控版本证明自检能失败。Quartus 的分析综合、布局布线、汇编和 TimeQuest 状态分别记录；负 slack 或遗漏约束不能算时序通过。未核对实物与未运行 Programmer 时，一律不声称完成下载或板级观测。
